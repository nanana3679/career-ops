## 자소서 워크플로 오버라이드 (CRITICAL)

**career-ops의 기본 apply 모드는 "폼 1회 생성" 중심. 사용자는 반드시 아래 단계를 따를 것**:

### 1. 공고 분석
- `reports/`에 저장. 과거 공고 분석 스타일은 `docs/past-postings/` 참고
- 표면 요구사항 / 진짜 핵심 / 신입 진입 난이도 / 경험 매칭 3가지 추출

### 2. 자소서 방향 제시 (초안 아님)
- 방향 A/B/C 제안
- 각 방향이 사용자의 어떤 경험에 근거하는지 명시
- 사용자가 고르기 전에는 초안 작성 금지

### 3. 초안 작성
- 사용자가 방향을 선택한 후
- `/cover-letter` 스킬 실행 (`.claude/skills/cover-letter/SKILL.md`의 8단계 워크플로)
- `cover-letters/*.md`의 톤/구조 참조 (CJ물류, GS, 한화ICT, 현대오토에버, LIG 사례)

### 4. 면접관 에이전트 리뷰 (필수)
자소서 작성/수정 후 반드시 진행. `/cover-letter review` 실행 (`.claude/skills/cover-letter/review.md`):
- 첫인상 + 항목별 강약점 + 떡밥/과잉증명 판단
- 필살기 분석 (면접 질문을 유도하는가?)
- 예상 면접 질문 리스트 (면접관 의도 + 답변 방향 + 필수 키워드)
- 구체적 수정 제안

### 자소서 원칙 (`cover-letters/strategy.md` 반영)
- 자소서는 면접 유도 도구. 모든 걸 증명하지 않음
- 필살기 / 빌살기 / 밉살기 프레임워크
- 두괄식 = 면접 주도권 확보
- 구현 디테일은 면접에서 물어보게 남겨둘 것
- AI 생성 흔적 제거: 문장 길이 다양화, '열정/혁신/시너지' 등 제거
- AI가 생성한 기업 수치는 반드시 팩트체크

## 평가 (오퍼) 특이사항

**6년+ 경력 요구 JD는 SKIP 권고**. 사용자는 실무 경력 0년 (개인/팀 프로젝트만). 경력 요구사항이 3년 이상이면 기본 SKIP, 신입/주니어 명시 JD를 우선 평가.

**"신입 진입 난이도" 항목을 평가 리포트에 추가**:
- 낮음 / 중간 / 높음
- 근거: 우대사항이 신입에게 현실적인가, 표면 요구사항과 진짜 핵심의 간극

**대면 면접 허들**:
- hada가 배포 미완 → 완성된 배포본 증빙 약함. 이 점은 자소서에서 회고로 다룰 것 (hada-reboot 진행 중 명시)
- 첫 면접 경험 축적 중요 → 과도하게 필터링하지 말 것
