# 한화시스템 ICT서비스 자기소개서 — 서비스 개발/운영

## 1. 직무 역량과 노력 (1000자)

> 지원 직무와 관련하여, 본인이 지금까지 기울여 온 구체적인 노력과 이를 통해 습득한 직무(또는 기술) 역량을 서술해 주십시오.

분양 모델하우스에서 5개월간 ERP 시스템을 운영하며 고객사 시스템 운영의 핵심을 현장에서 체감했습니다. 사용자의 업무 흐름을 이해하지 못하면 시스템이 현장에서 작동하지 않는다는 것, 그리고 문제의 근본 원인을 구조적으로 해결해야 같은 문제가 반복되지 않는다는 것입니다.

오픈 첫날 150건의 상담 데이터를 처리하며 수기 통계가 전부 불일치한 경험을 했습니다. 원인은 데이터 입력과 통계 산출이 분리되지 않은 구조였습니다. 다음 날 단일진실공급원 기반의 자동 통계 체계를 설계하여 실수를 하루 0~1건으로 줄였습니다. 이후 200건의 계약서 상태를 파악하려면 실물 박스를 뒤져야 했고, 수기 기록은 바쁜 상황에서 반드시 누락이 발생했습니다. 추적 불가능한 항목을 기계적으로 추적 가능한 항목으로 교체하는 원리를 적용하여, 30분 이상 걸리던 상태 파악을 클릭 몇 번으로 단축하는 자동 추적 체계를 정착시켰습니다.

이 현장 감각 위에 프론트엔드와 백엔드를 아우르는 개발 역량을 쌓았습니다. 한국어 단어 암기 앱 hada에서는 프론트엔드 전체를 담당하고 백엔드와 API를 함께 설계했습니다. 별개로 보이던 네 가지 문제의 근본 원인을 추적하여 결정적 셔플 알고리즘으로 해결했고, 이후 서버리스 아키텍처로 마이그레이션하며 ORM 기반 스키마 설계, 인증 시스템 구축, CI/CD 파이프라인 자동화를 직접 수행했습니다. 초기 배포 시 발생한 연쇄 장애를 순차적으로 진단하며 SSR/CSR 경계 관리와 체계적 에러 로그 분석 역량을 쌓았습니다. 현장에서 시스템 운영을 직접 경험하며 쌓은 업무 이해 역량과 풀스택 개발 역량을 결합하여 고객사에 실질적인 가치를 제공하겠습니다.

## 2. 협업 경험 (700자)

> 공동의 목표 달성을 위해 협업했던 경험을, 본인이 수행한 역할을 중심으로 서술해 주십시오.

한국어 단어 암기 앱 hada를 백엔드 개발자와 함께 개발했습니다. 기존 Anki의 학습 효과는 유지하되 복잡한 설정 없이 즉시 사용할 수 있는 앱이 목표였습니다. 저는 프로젝트를 기획하고 프론트엔드 전체를 담당했으며, 백엔드 팀원과 함께 API를 설계했습니다.

초기에는 진행 상황이 공유되지 않아 중복 작업과 대기가 발생했습니다. 칸반보드를 도입하여 각자의 작업을 가시화하고, 정기 회의와 즉시 통화를 병행해 변경사항을 실시간으로 공유했습니다.

가장 어려웠던 점은 구현 중 예상하지 못한 요구사항이 계속 드러난 것입니다. 날짜 경계 처리, 학습 상태 스냅샷 등 새로운 요구가 발견될 때마다 API 설계와 스키마가 함께 변경되어야 했습니다. 변경의 영향 범위를 파악하고 백엔드와 동기화하는 과정에서, 의견이 다르면 바로 결론 내지 않고 각자 근거를 조사한 뒤 다시 토론했습니다. 학습 데이터에 문법 요소를 포함할지 논의할 때는 주변 한국어 학습자들에게 직접 물어본 뒤 결정했고, 제 의견이 기각되었지만 사용자 피드백에 기반한 결정이라 납득했습니다.

이 경험에서 체득한 원칙은 두 가지입니다. 변경사항은 발생 즉시 공유하고, 의견 차이는 사용자 데이터로 해소한다는 것입니다.

## 3. 대학생활에서 시간과 열정을 쏟은 일 (700자)

> 대학생활 동안 본인이 가장 중요하게 생각하며 시간과 열정을 쏟았던 일은 무엇이며, 이를 통해 어떤 성취를 이루었는지 서술해 주십시오. 해당 경험을 본인만의 가치관 또는 개성과 연관지어 작성해 주십시오.

웹 서비스를 기획부터 배포까지 직접 만드는 일에 가장 많은 시간을 쏟았습니다. 단순히 기술을 익히는 것이 아니라, 실제 사용자의 문제를 소프트웨어로 해결하는 경험을 쌓고 싶었습니다.

그러나 열정만으로는 부족했습니다. hada는 기술적으로 거의 완성했지만 배포에 이르지 못했습니다. 기획이 충분하지 않아 엣지케이스가 계속 발견되었고, Anki라는 오픈소스 선례가 있었는데도 참고하지 않아 이미 해결된 문제를 처음부터 시행착오했습니다. Wordle 덱 플랫폼은 배포까지 완료했지만, 사용자가 Wordle을 당연히 알 거라 가정하여 튜토리얼을 만들지 않았고, 콜드 스타트 문제를 겪으며 기능 완성만으로는 서비스가 성립하지 않는다는 교훈을 얻었습니다.

이 실패들에서 확립된 가치관은 "문제의 표면이 아니라 구조를 보자"입니다. 모델하우스에서도 과장님들이 하루종일 일하는 저를 안쓰러워했지만, 계속 바뀌는 요구사항에 맞춰 엑셀 양식과 함수를 설계하는 과정에서 보람을 느꼈습니다. 하찮아 보이는 문제에서도 구조적 개선점을 찾는 일이 저에게는 의미 있는 일입니다. 이 태도로 고객사의 시스템을 단순히 유지하는 것이 아니라, 운영하며 발견한 구조적 비효율을 개선하는 개발자가 되겠습니다.
