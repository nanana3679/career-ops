# 현대오토에버 자기소개서 — 프론트엔드 개발

## 1. 지원 동기 및 커리어 계획 (500~1000자)

> 현대오토에버의 해당 직무에 지원한 이유와 앞으로 현대오토에버에서 키워 나갈 커리어 계획을 작성해주시기 바랍니다.

반복되는 문제의 개별 증상이 아닌 구조적 원인을 찾는 것이 제 개발 방식입니다. 이 사고방식은 개발 프로젝트와 엔터프라이즈 현장, 두 가지 경험에서 형성되었습니다.

한국어 학습 앱 'hada'를 기획하고 프론트엔드를 구현하면서, 11개 언어 58,000개 어휘를 다루는 다국어 서비스를 설계했습니다. 간격 반복 알고리즘의 복잡한 상태 관리를 사용자에게는 단순한 학습 화면으로 전달해야 했고, 시스템이 복잡할수록 그 복잡도를 감추는 프론트엔드의 역할이 커진다는 것을 체감했습니다.

모델하우스에서는 5개월간 엑셀과 ERP로 계약서를 처리하고 상담 데이터를 관리하며, 시스템을 만드는 쪽이 아닌 현장에서 쓰는 쪽의 시선을 경험했습니다. 화면이 업무 흐름과 맞지 않을 때 실수가 구조적으로 반복되는 것을 직접 겪었고, 이를 자동화 체계로 개선하면서 기술과 현장의 접점을 만드는 일에 확신이 생겼습니다.

현대오토에버는 현대자동차그룹의 제조, 판매, 서비스 전 영역의 IT 시스템을 구축합니다. 글로벌 환경에서 다양한 사용자와 복잡한 비즈니스 로직이 하나의 플랫폼에 존재하는 환경입니다. 여기서 프론트엔드는 시스템의 복잡도를 사용자에게 전달하지 않는 계층이라고 생각합니다. 다국어 서비스를 직접 설계한 경험과 엔터프라이즈 시스템을 현장에서 운영한 경험이 이 역할에 기여할 수 있다고 판단하여 지원합니다.

입사 후에는 담당 시스템의 업무 도메인을 현장 사용자 시선에서 먼저 파악하겠습니다. 모델하우스에서 ERP를 직접 사용하며 업무 흐름을 파악한 뒤에야 올바른 개선을 할 수 있었던 것처럼, 화면을 만들기 전에 그 화면이 어떤 업무 맥락에서 사용되는지 이해하는 것이 먼저입니다. 장기적으로는 시스템 규모가 커져도 사용자 경험은 단순하게 유지되는 프론트엔드 아키텍처를 설계하는 엔지니어로 성장하겠습니다.

## 2. 직무 역량 및 노력/경험 (500~1500자)

> 지원 직무와 관련하여 어떠한 역량을(지식/기술 등) 강점으로 가지고 있는지, 그 역량을 갖추기 위해 무슨 노력과 경험을 했는지 구체적으로 작성해주시기 바랍니다. (학내외 활동/프로젝트/교육 이수 과정 등 본인의 경험을 기반으로 작성해주시기 바랍니다.)

개별 증상이 아닌 구조적 원인을 진단하는 설계 능력과, TypeScript·React·Next.js 기반의 웹 서비스를 기획부터 배포까지 수행한 실행 경험이 핵심 역량입니다.

한국어 단어 암기 앱 'hada'에서 프론트엔드를 담당했습니다. 간격 반복 알고리즘(FSRS)을 통합하고 학습 흐름을 설계하는 과정에서, 새로고침 시 진도 유실, prefetch 대상 불확실, 학습량 변경 시 순서 충돌, 서버의 상태 관리 부담이라는 네 가지 문제가 동시에 발생했습니다. 처음에는 새로고침 문제를 로컬 저장소로, prefetch 문제를 별도 큐로 각각 해결하려 했습니다. 그러나 원인을 추적하니 네 문제 모두 하나의 설계 결함에서 비롯된 것이었습니다. 이 근본 원인을 제거하는 결정적 셔플 알고리즘을 설계했고, 파생 문제들이 자연스럽게 해결되었습니다.

이 프로젝트에서 백엔드 개발자와 API를 공동 설계하고, 기획 단계에서 예측하지 못한 엣지케이스가 구현 중 발견될 때마다 스키마 변경과 요구사항 조율을 반복했습니다. 의견이 다를 때는 각자 근거를 조사한 뒤 토론하여 합의를 이끌어내는 것이 팀의 원칙이었고, 주요 설계 결정은 트레이드오프를 분석한 문서로 남겨 의사결정 과정을 추적할 수 있게 했습니다. 데이터를 과도하게 정규화하여 불필요한 복잡도를 만든 경험도 있었고, 이를 통해 설계 시점에 결정의 파급 효과를 평가하는 습관을 체득했습니다. 11개 언어 다국어 지원과 반응형 UI도 직접 구현했습니다.

Wordle 덱 공유 플랫폼은 기획부터 배포까지 단독으로 수행했습니다. 카카오톡 공유 시 최신 덱 정보가 미리보기에 반영되도록 ISR을 적용했고, 좋아요 기능에는 Optimistic UI와 쓰로틀링을 결합하여 즉각적인 반응과 서버 부하 방지를 동시에 달성했습니다. 배포 후 콜드 스타트 문제를 경험하며 기능 완성도와 별개로 사용자 확보 전략의 중요성을 배웠습니다.

모델하우스에서는 엔터프라이즈 시스템의 현장 사용자 관점을 체득했습니다. 오픈 첫날 상담 150건의 통계가 전부 불일치하는 사고 이후, 데이터 입력과 검증을 분리하는 구조를 설계하여 오류를 하루 0~1건으로 줄였습니다. 계약서 상태 추적 문제에서는, 관리자의 수기 기록 지시에 대해 사람의 기록에 의존하는 것 자체가 구조적 원인이라 판단하고, 기계적으로 추적 가능한 대안을 설계하여 현장 표준 프로세스로 정착시켰습니다. 업무를 인수인계할 때는 잘못된 입력에 즉시 색깔이 바뀌는 오류 가시화를 적용하여, 담당자가 바뀌어도 품질이 유지되는 체계를 만들었습니다.

개발 프로젝트에서는 구조적 원인을 찾아 해결하는 설계를, 현장에서는 시스템이 실제로 쓰이는 맥락을 경험했습니다. 이 두 역량을 결합하여 현대오토에버의 엔터프라이즈 프론트엔드에 기여하겠습니다.
