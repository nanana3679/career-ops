# cover-letter — 자소서 작성 스킬

## Mode Routing

| Input | 동작 |
|-------|------|
| (empty / `write`) | 자소서 작성 전체 워크플로 (아래 8단계) |
| `review` | 작성된 자소서를 면접관 관점에서 리뷰 (→ `review.md` 참조) |

---

## 원칙 (항상 적용)

- 자소서에서 모든 것을 증명하지 않는다. 증명은 면접에서 한다.
- 자소서는 면접관이 특정 질문을 하도록 유도하는 도구.
- 필살기가 있다면 그 내용으로 면접관이 질문하도록 유도.
- 구현 디테일은 면접에서 물어보게 남겨둔다.
- 사용자의 번아웃 컨텍스트 준수 (`modes/_profile.md`): 감정적 압박 X, 사실 기반 분석 O.

---

## 입력

사용자가 다음 정보를 제공한다:
- 기업명과 채용공고 (URL 또는 텍스트 또는 이미지)
- 자소서 항목별 문항과 글자수 제한
- (선택) 특별히 강조하고 싶은 경험이나 방향

---

## 사전 단계: 전략 및 사용자 컨텍스트 확인

다음 파일을 먼저 읽는다:
- `cover-letters/strategy.md` — 필살기 프레임워크, 구루의 언어, 3C4P, 두괄식
- `modes/_profile.md` — 사용자 컨텍스트, 자소서 워크플로 규칙, archetypes
- `config/profile.yml` — candidate 정보, narrative, archetypes

---

## 1단계: 기업 조사

채용공고를 분석하고 웹 검색으로 기업의 최신 정보를 조사한다.

**조사 항목**:
- 기업이 지금 해결하고 싶은 문제 (사업 전략, 최신 뉴스)
- 지원 직무가 그 문제와 어떻게 연결되는지
- 채용공고에서 반복되는 핵심 키워드 5개 추출
- 경쟁사 대비 차별점
- 최근 산업 동향, 신사업, 투자 계획, 기술 트렌드
- 해당 직무 관련 최신 이슈 (신기술 도입, 조직 변화, 채용 방향 등)

조사한 이슈를 자소서 마무리(발휘방안/포부)에 자연스럽게 녹일 수 있도록 정리한다.
"산업 → 회사의 위치 → 내가 하고 싶은 역할" 흐름에 활용한다.

결과를 `cover-letters/{기업명}-research.md`에 저장. 기존 파일 있으면 업데이트.

---

## 2단계: 경험 매칭

### 2-1. JD 핵심 역량 추출
JD의 핵심 역량/우대사항을 추출한다.

### 2-2. 경험 데이터 로드
다음 파일을 모두 읽는다:
- `cv.md` — 이력서 (메인, 프론트엔드 중심)
- `article-digest.md` — 필살기 포함 모든 proof points (4개 프로젝트 + 모델하우스 + 사고패턴 + 약점 + 진행계획)
- `cover-letters/questions.md` — 자주 받는 자소서 질문과 답변
- `interview-prep/story-bank.md` — STAR+R 스토리
- `modes/_profile.md` — archetype별 강조점 매핑
- (대체 트랙 지원 시) `cv-alternate/it-admin.md` 또는 `cv-alternate/web-publisher.md`

### 2-3. 필살기 프레임워크 분류
경험을 필살기/빌살기/밉살기로 분류 (`cover-letters/strategy.md` 기준):

| 경험 | 직무 유사성 | 성공 성과 | 등급 |
|------|------------|----------|------|
| ... | 높음/보통/낮음 | 수치 포함 여부 | 필살기/빌살기/밉살기 |

### 2-4. JD 역량별 매칭 테이블
커버리지 100%를 목표로 JD 역량별 매칭 경험을 배치한다.

| JD 역량 | 매칭 경험 | 배치 항목 |
|---------|----------|----------|
| ... | ... | ... |

각 자소서 항목에 어떤 경험을 배치할지 매핑.

---

## 2.5단계: 서사 설계 (사용자 확인 필수)

초안 작성 **전에** 자소서 전체 서사를 설계하고 사용자에게 방향 확인을 받는다.

1. **한 줄 캐릭터**: "이 회사에서 나는 ___한 사람이다" — 자소서 전체를 관통하는 정체성.
2. **항목 간 흐름**: 필살기(1번 항목)를 축으로 나머지 항목들이 어떻게 보강하는지.
   - 예: 필살기(기술적 문제 해결) → 보강(협업/소통) → 보강(성장 과정)
3. **떡밥 맵**: 각 항목에서 면접관에게 유도할 질문 1개씩 미리 설계.
   - 형식: `항목 N → 떡밥: "..." → 유도 질문: "..."`
4. **문항별 전략**: 문항 유형에 따라 적합한 구조 선택 (KKK+STAR / STAR-F / 3C4P / 두괄식+스토리텔링).

**이 단계 결과를 사용자에게 보여주고 방향을 확인받은 뒤 3단계로.**

---

## 3단계: 원본 초안 작성 (글자수 무제한)

글자수 제한 없이 넉넉하게 작성한다.

### 문항 유형별 작성 가이드

#### 직무역량/지식기술 발휘
- 구조: KKK+STAR 또는 STAR-F
- 핵심: "경험 나열"이 아니라 "경험 → 발휘방안" 연결
- 결론에 반드시 지원 직무에서 어떻게 활용할지 미래형

#### 이수과목/교육 문항
- 구조: 학습 주제 → 핵심 내용 → 실제 수행 경험 또는 산출물 → 직무 활용
- 핵심: "얼마나 오래 했는가"보다 "무엇을 배웠고 무엇을 할 수 있는가"

#### 프로젝트 완수/문제해결 경험
- 구조: STAR 또는 3C4P
- 핵심: 문제를 분리/구조화하여 해결한 과정 + 정량 성과
- A(행동)에 가장 많은 분량 할애

#### 가치관/성격/장단점
- 구조: 두괄식 + 스토리텔링
- 핵심: 가치관 형성 계기(경험) → 회사에서의 실현 방법

#### 지원동기
- 구조: KKK (기업 이해 → 나와의 접점 → 기여 의지)
- 핵심: 기업의 고유한 가치/사업 + 내 경험의 교차점

#### 입사 후 포부
- 구조: 단기(1~2년) → 중기(3~5년) 목표
- 핵심: 구체적 직무 활동 + 성장 방향

### 핵심 강점 방향

"문제가 터지기 전에 미리 구조를 설계하고 개선하는 사람"
- "사후 대응"이 아닌 "사전 설계/사전 정의" 관점을 앞세울 것
- "먼저 리스크를 정의했다", "설계 단계에서 적용했다", "반복되기 전에 구조를 전환했다"

### 글쓰기 3대 원칙

1. **경험을 나열하지 말고 구조화하여 써라**
   - 경험 A, B, C를 콤마로 잇지 말고, 하나의 흐름(인식→판단→실행→결과)으로 엮기

2. **결과를 강조하지 말고 판단 과정을 드러내라**
   - "~했다"보다 "왜 그 방법을 선택했는지"가 먼저
   - 예: ✕ "Hybrid Retrieval을 적용했고" → ✓ "누락 원인이 검색 정확도에 있다고 판단해 Hybrid Retrieval을 적용했고"

3. **활동을 나열하지 말고 문제 해결 흐름을 설계하라**
   - "A로 ~하고, B로 ~하고, C로 ~했다" 식 나열 금지
   - 문제↔솔루션 1:1 대응으로 흐름 만들기

### 글쓰기 세부 규칙
- 왜 그 문제를 중요하게 봤는지 / 어떤 판단과 선택을 했는지 / 지금의 태도와 일하는 방식으로 어떻게 이어졌는지
- 중간점(·) 제거
- 성과와 핵심 경험을 강조하고 가능하면 앞쪽부터
- 부제목은 경험을 압축적으로
- 단문 위주 간결 (단소수 원칙)
- 소제목으로 가독성 확보 (글자수 여유 시)
- 수치/지표 적극 활용

### 문체
- 28세 한국인 취준생 말투
- 문장 길이 극도로 다양화 (30%는 15자 이내 단문)
- 금지 단어: 열정, 혁신, 시너지, 역량 강화, 기여하겠습니다 (마지막 문장 제외)
- AI 냄새 나는 매끄러운 문장 지양 — 의도적으로 투박하게
- 구루의 언어: 전문 서적이나 아티클의 개념으로 경험을 재정의

### 시제 규칙
- 경험/사실 → 과거형
- 준비 과정 → 과거형, 현재 유지되는 상태 → 현재형
- 입사 후 기여/다짐 → 미래형

### 전략 체크
- 자소서에서 모든 것을 증명하지 않는다
- 면접관이 특정 질문을 하도록 유도하는 떡밥 배치
- 필살기로 면접관 질문 유도
- 구현 디테일은 면접에서 물어보게 남겨둠

결과를 `cover-letters/{기업명}-full.md`에 저장. 각 항목 끝에 현재 글자수(공백 포함) 표시.

---

## 4단계: 팩트체크

초안에서 사용한 기업 정보, 수치, 뉴스가 정확한지 검증:
- 웹 검색으로 교차 확인
- 출처 불확실한 수치는 제거하거나 표현 완화
- 경험에서 언급한 수치가 `article-digest.md` 내용과 일치하는지 확인

---

## 5단계: 압축 버전 작성

원본(`-full.md`)을 글자수 제한에 맞춰 압축.

**압축 원칙**:
- 각 항목의 글자수 제한 반드시 준수 (공백 포함, 90~100% 목표)
- 삭제한 부분은 면접에서 말할 수 있으므로 아까워하지 않는다
- 필살기와 떡밥은 반드시 살린다
- 의미가 약한 문장부터 제거
- 압축하면서 문장을 합치거나 재구성 가능

결과를 `cover-letters/{기업명}.md`에 저장. 각 항목에 글자수 표시.

---

## 6단계: AI 유사성 제거 점검

작성 후 아래 7가지 패턴을 반드시 점검. **2개 이상 해당되면 수정 필요**.

### 표현 패턴
- "~이 아니라 ~" 대조 구문: 한 문항에 2회 이상 금지
- "N개 축으로 나눠 접근": 전체 자소서에서 1회만 허용
- "~가 아니라" 표현: 최대한 완화, 긍정형으로

### 구조 패턴
- "기여하겠습니다" 반복: 문항별로 변주
- "~했습니다" 연속 4문장 이상 금지: 종결어미 변주
- 문항 간 톤 균일성: 4개 문항 모두 같은 리듬이면 1~2개 톤 변경

### 인간미 패턴
- 감정/생각 부재: 각 문항에 최소 1곳 당시 심정/판단 동기 짧게
- 문장마다 내 생각/판단/감정 한 줄 섞기

---

## 7단계: 최종 체크리스트

- [ ] 글자수 범위 준수
- [ ] 중간점(·) 0개
- [ ] AI 유사성 제거 (6단계 전체 통과)
- [ ] 각 문항에 발휘방안/미래 연결 포함
- [ ] 문항 가이드 세부 요구사항 전부 충족
- [ ] JD 역량 매칭 테이블 커버리지 100%
- [ ] 블라인드 채용 시 학교/학과명 익명화
- [ ] 시제 규칙 준수 (과거/현재/미래)
- [ ] 경험 간 자연스러운 연결 (나열 금지)
- [ ] 성과에 수치/지표 포함
- [ ] 글쓰기 3대 원칙 준수

---

## 8단계: 사용자 검토 요청

원본과 압축 버전을 비교할 수 있게 제시하고 다음 안내:

1. **원본 참고**: 압축 과정에서 빠진 내용 중 살리고 싶은 부분 있는지
2. **30% 직접 수정 필요**: AI 문장은 매끄러워서 티가 남. 본인 문체로 디테일 추가
3. **항목별 피드백**: 각 항목 수정 희망 부분
4. **떡밥 확인**: 면접에서 유도하고 싶은 질문

사용자 수정 완료 후 **면접관 리뷰 진행** (`/cover-letter review` 또는 수동으로 `review.md` 실행).

---

## 주의사항

- **할루시네이션 체크**: AI가 생성한 기업 뉴스나 수치는 반드시 팩트체크
- **표절 위험**: 남들과 똑같은 문장 방지 위해 문장 구조 꼬기
- **레퍼런스 참고만**: `cover-letters/` 디렉토리의 기존 자소서는 톤/구조 참고용. 문장 재사용 금지
- **기업별 강조점 차별**: 같은 경험이라도 기업에 맞게 강조점 변경
- **사용자 방향 확인 필수**: 2.5단계(서사 설계)와 8단계(검토)에서 사용자 확인 없이 진행 금지
