# cover-letter review — 면접관 관점 리뷰

자기소개서를 면접관 관점에서 리뷰한다.

## 입력

사용자가 리뷰할 자소서 파일 경로를 제공한다.
경로가 없으면 `cover-letters/` 디렉토리에서 가장 최근 수정된 자소서(기업명에서 `-research.md`, `-full.md`, `-review.md` 제외한 `{기업명}.md`)를 찾는다.

## 준비

리뷰 전에 다음 파일을 모두 읽는다:
- 대상 자소서 (`cover-letters/{기업명}.md`)
- 해당 기업 조사 파일 (`cover-letters/{기업명}-research.md`)
- `cv.md` — 이력서
- `article-digest.md` — 필살기 및 proof points
- `modes/_profile.md` — 사용자 컨텍스트
- `config/profile.yml` — 프로필 데이터
- `cover-letters/strategy.md` — 필살기 / 구루의 언어 / 3C4P / 두괄식
- `cover-letters/questions.md` — 자주 받는 자소서 질문
- `interview-prep/story-bank.md` — STAR+R 스토리 (있으면)

## 리뷰 수행

면접관 역할로 다음 4가지를 분석한다.

### 1. 자소서 전반 피드백

- **첫인상**: 서류 더미에서 이 자소서를 읽었을 때 드는 인상
- **항목별 강약점**: 각 항목이 설득력 있는지, 약한 부분은 어디인지
- **떡밥 vs 과잉증명**: 면접에서 질문 유도 떡밥 vs 자소서에서 너무 많이 증명하려 하는지
- **일관성**: 전체 항목을 관통하는 메시지 존재 여부
- **AI 냄새**: 기계적으로 매끄러운 문장, 반복 패턴, 전형적 AI 어휘

### 2. 필살기 분석

- 이 자소서의 필살기가 무엇인지 식별
- 필살기가 면접관 질문을 유도하도록 설계되어 있는지
- 필살기 등급 평가 (직무 유사성 × 성공 성과 × 인사이트)
- 필살기 부족 시 `article-digest.md`에서 더 강력한 후보 제안

### 3. 예상 면접 질문 리스트

각 항목에서 면접관이 물어볼 법한 질문 생성.

형식:
```
| # | 질문 | 면접관 의도 | 답변 방향 | 필수 키워드 |
|---|------|-----------|----------|-----------|
```

질문 유형:
- **검증 질문**: 자소서 내용이 진짜인지 파고드는 질문
- **심화 질문**: 의도적으로 남겨둔 디테일을 묻는 질문
- **약점 공략**: 약하거나 모호한 부분을 찌르는 질문
- **상황 질문**: "그런 상황이 다시 오면 어떻게 하겠습니까?" 류

### 4. 구체적 수정 제안

- 문장 단위 수정 제안 (원문 → 수정안)
- 추가해야 할 내용
- 삭제해야 할 내용
- 구조 변경이 필요한 부분

## 결과 저장

리뷰 결과를 `cover-letters/{기업명}-review.md`에 저장.

## 핵심 원칙

- 자소서에서 모든 것을 증명할 필요 없음. 증명은 면접에서 할 일.
- 자소서는 면접관이 특정 질문을 하도록 유도하는 도구.
- 필살기가 있다면 그 내용으로 면접관이 질문하도록 유도해야 함.
- 구현 디테일은 면접에서 물어보게 남겨둔다.
- 경험 파일(`article-digest.md`, `cv.md`)의 내용과 자소서의 내용이 일치하는지 반드시 확인.

## 팔로우업

리뷰 결과 공유 후 사용자에게 다음을 안내:
1. 수정 제안 중 반영할 항목 선택
2. 예상 질문 중 준비가 부족한 항목은 `interview-prep/story-bank.md`에 추가
3. 수정 완료 후 재리뷰 필요 시 재실행
